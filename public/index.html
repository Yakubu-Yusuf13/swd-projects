02 / Data model

A normalized model with clear links.

Enrollment and class-subject offerings resolve the many-to-many relationships without duplicating student, teacher, or subject details.

Core entities

studentsteachers school_classessubjects termsenrollments class_subject_offeringsresults attendance
Integrity rule: A result's enrollment and subject offering must belong to the same class and term. Triggers enforce this without repeating class and term columns in each result.

Relationships

  • 1:NTeacher → form classes and subject offerings
  • 1:NStudent → term enrollments → class placements
  • M:NClasses ↔ subjects, resolved by class subject offerings
  • 1:NEnrollment and offering → student subject results
  • 1:NStudent → daily attendance records

05 / Get started

Load the sample database.

Run the files from the repository folder in this order. The seed contains fictional sample records.

mysql -u root < schema.sql
mysql -u root < seed.sql
mysql -u root < indexes.sql
mysql -u root < queries.sql
mysql -u root < procedures.sql
mysql -u root < transactions.sql
schema.sql tables & rules ↗ seed.sql sample data ↗ queries.sql reports & views ↗ indexes.sql query plans ↗ procedures.sql result upsert ↗ transactions.sql audited transfer ↗
06 / Backup

Take the database with you.

Exporting structure and data produces a portable SQL backup that can be restored in phpMyAdmin.

  1. In phpMyAdmin, select swd_school in the left navigation, then open Export.
  2. Choose Custom and SQL; select all tables and include both structure and data.
  3. Include views, triggers, and routines if those export options are available. Choose Save output to a file and click Go.
  4. Save the download as database.sql. To restore it, select a target database, open Import, choose the file, and click Go.
